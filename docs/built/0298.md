## §298 — technic.html opens in the tour

Owner: "For the Lego builds, start in the tour mode." The page now OPENS in
§294's carousel, at the first stop, instead of on the whole table. Display
only: no placement, probe of the build or `.ldr` moves.

**The table** (`initialTour(search, stops)` in `src/technic-carousel.js`, the
one law the page and the probe read; `?x` means the key is present, whatever
its value):

| query | opens | why |
|---|---|---|
| none, or only `panel` / `loop` / `auto` / `gen` / `view` | tour at stop 1 | the default |
| `?tour=1`, `?tour=`, `?tour=yes` | tour at stop 1 | only a literal `0` is "off" |
| `?tour=0` | overview | the old default, kept as a link |
| `?cell=<stop>` | tour at that stop | §294, unchanged; case forgiven |
| `?cell=<anything else, even empty>` | overview | as §294; a bad link is not guessed at |
| `?focus=<anything, valid or not>` | no tour (the focus lands as before) | every link that predates the carousel lands exactly where it did |
| `?cell=<stop>&focus=<x>` | tour at the cell | the cell won in §294 too |
| `?tour=0&cell=<stop>` | tour at the cell | a named place beats "no tour" |

An invalid `?focus=` is "no auto tour" rather than "tour": the old page showed
the overview for it, and the smoke test compares every focus value and a bogus
one against the pre-change page, camera and visible-cell count.

**Only the first build asks.** `build()` reads `initialTour` once
(`firstBuild`); every later build keeps the tour as it stands (the stop if in
the tour, the overview if not). Without that, the generation buttons would
re-enter the tour the reader had just left, because the URL no longer names a
cell. **The URL writer keeps its single-writer rule** (`writeUrl`, called by
`tourGo`/`tourExit`): opening in the tour goes through `tourGo`, so a plain
load rewrites the address to `?cell=row-1` exactly as entering by hand does;
`?tour=0` loads write nothing. Leaving the tour now writes `tour=0` (entering
removes it), so the address says what is on screen and a reload after
Escape stays in the overview instead of walking back in.

**The opening frame.** Stop 1 (`row-1`, the centre to fourth row) is a good
first frame, not a poor one: a four-axle train on its base with the bar's
"1 / 10 — centre→fourth" and the `overview` button in view, one cell shown, its
panel row lit. Two things were wrong and one is left. Fixed: the lit row was
`scrollIntoView({block:'start'})`ed, which on load scrolled the panel's title,
generation buttons and "tour the cells" past the top; it is `nearest` now
(only moves a row that is out of view), and the default opening at stop 1
does not scroll at all (`tourGo`'s `opening`), so the panel opens on its header. Left alone: the cell's big in-scene label
("1. centre→fourth") draws through the gears (depthTest off, §294's); proposed,
not done, a smaller or offset label in the tour. The stop order is unchanged.

**Links.** `index.html` links `technic.html?view=lego` (`view` is read by
nothing; it now lands in the tour, which is the intent). Nothing else in the
repo, docs or tools assumed the overview default except §294's own smoke
test, updated here. No file the service worker precaches changed names.

**Instruments.** `tools/probe-technic-carousel.mjs` holds the table over the
real stops (and its mirror in the writer's URLs), the page reading
`initialTour` once and only at the first build; controls for a default that
ignores `?focus=`, one that ignores `?tour=0`, one that tours a bad `?cell=`,
and a page that asks on every build. `tools/smoke-technic-carousel.mjs`
(Chromium) at 1280x800 and 390x844: the plain load is the tour at stop 1 with
"1 / 10 — …", one cell, the row lit, `?cell=row-1` written and the overview
button present; `?tour=0` against the pre-change page (`--baseline REF`,
default `origin/main`, read through `git archive`; skipped aloud if that ref
already has `initialTour`) is camera 0 and the same cell count, as is every
`?focus=` value, a bogus one, `?cell=bogus`; generation switch in the tour
keeps the stop and in the overview stays; Escape reaches the overview, a
rebuild and a reload stay there.

**What the battery cannot see:** all of it. technic.html imports `layout.js`
and nothing from the movement; the battery never loads it, and the first
frame's look is the screenshot's, not a gate's.
