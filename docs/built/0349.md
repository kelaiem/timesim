## §349 — A usage report the visitor previews and sends themselves — PARTIAL: landing 1 (the table, the tally and the preview) shipped

**The ask** (the owner, 2026-11-18): a lightweight usage-metrics mechanism that lets a visitor preview a report
of the features they explored and send it by email or as a GitHub post. The site has no backend (§26) and no
analytics (§340 says so), so the shape follows: **the app transmits nothing**, and a report leaves only when the
visitor sends it. The owner's rulings the same day: email goes to an address the visitor types (none ships in the
source), counting is once per session and the tally stays in memory until the visitor turns remembering on, the
GitHub route is a Discussions category for now, a spec field reports its name only unless a dropdown chose the
value, and the Technic carousel's cells are not counted.

Landing 1 is the table, the tally, the preview and Copy, in English. Landing 2 (the email and GitHub buttons, the
remember toggle, the tour's closing offer, the maintainer's tally tool, the strings in every locale) and landing 3
(the other pages) remain in the private roadmap's §349.

### The table (`src/usage.js`, pure)

- **`USAGE_FEATURES` is the only list of things that can be counted**: 81 rows in eight groups (view, camera,
  guided, explore, operate, alarm, build, appearance). 34 of them are generated from `SPEC_FIELDS`, one per spec
  key a deep link can carry. `mark()` refuses a key not in the table, a via not in `VIA`, and a value on a row that
  takes none, so the tally cannot hold free text, a URL or a part name. The privacy property is structure.
- **A value is recorded only from a dropdown.** A row that takes one declares `values: 'options'`, and the value
  must be on the `<select>`'s own option list, read off the control at the moment of choice. 8 dropdowns qualify:
  position, quality, and the six reload-tier spec selects.
- **Which part, never.** `focus` and `unit` count that the feature was used. A list of the parts someone looked at
  is a browsing trail, and the ask was features.
- **The report is plain text and is the payload**: a format line, a header of build facts (release, environment,
  locale, renderer class, quality tier, a three-way viewport class), a counts line with the month (no day), then
  one line per group. `parseReport` reads it back strictly and returns any line outside the grammar as refused,
  because landing 2's tally tool will read public posts.

### What counts (`src/usage-ui.js`)

Nothing that counts is a setter. `setXray` and its siblings are also called by the state restore and by every
tour step, and neither is the visitor exploring.

- **Controls**: 52 elements in the two panels carry `data-usage="<key>"`. One delegated listener counts a TRUSTED
  click on a tagged button (`c`), and a trusted `change` on a form control inside a tagged element.
- **Shortcuts**: the shortcut table clicks the button it drives synchronously inside the trusted keydown, so an
  untrusted click during a trusted keydown counts as `k`. Any other untrusted click (a script, `?cycle`) counts
  nothing.
- **Gestures**: eight `usageMark` sites in `main.js` marking nine keys, each where the gesture commits: the winding crown
  turned (`wind`, or `setHands` when pulled) and tapped, the alarm crown turned and tapped, the column wheel
  pressed, a part tapped (`focus`), and the tour started and finished (`tour:*`, from `scriptStart` and the
  natural end, which only a tap reaches).
- **Links**: the parameter NAMES the page opened with (`l`). Values are never read off a URL.
- **When it is off**: under automation (`navigator.webdriver`, so the battery and every probe see nothing) unless
  `?usage=1`, on a `?trial` boot (§33), and under the native host (§338). It listens only from the build's last
  line, after the input guard is released, so nothing the build does counts. Landing 1 writes nothing to any
  storage.

### The preview

**Advanced → Usage report → Preview** opens a `<dialog>` whose editable box holds the report. Copy puts the box's
text on the clipboard exactly as edited, falling back to `execCommand` and then to selecting the text. Keys typed
in the box stop at the dialog, so they cannot reach the movement's shortcuts. The box stays `direction: ltr` and
the report stays canonical English in every locale (the dialog says so).

### What it measured

`tools/probe-349-usage.mjs` (Chromium, three boots, each rule with a control): the table against the surface both
ways (52 tags, 9 site keys, 81 rows, none unreached), the link's names only, a code click counting nothing and a
visitor's click counting `c`, a shortcut counting `k`, a dropdown's value recorded and a value-less dropdown's
not, the preview equal to the report, Copy equal to the edited box, typing in the box leaving x-ray as it was, the
tour's steps counting nothing beyond `tour:started`, the state restore (with a focus re-applied through `setFocus`)
counting nothing, nothing counted under automation, no usage key in storage, no request to another origin, no
`sendBeacon`, and a silent build. The native boot's fingerprint is unchanged (2402644439, 65 units).

### What it does not do yet, and one gap found

- **A reload ends the tally.** Every reload-tier control (the six spec dropdowns, the language, Reconfigure's
  Apply) reloads the page, and the in-memory tally goes with it. The next load counts the spec
  field's NAME from the link it reloads to, so a dropdown-chosen spec VALUE never reaches a report in landing 1.
  Only position and quality, which do not reload, keep their values. Carrying the tally across a reload the
  visitor caused needs storage, which the owner's ruling reserves for the remember toggle; the question is open in
  the roadmap.
- The new strings are English in every locale until landing 2; t() falls back to them visibly.
