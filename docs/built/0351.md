## §351 — A spec solver with a constraint ladder, a compromise budget and feature maturity tiers — PARTIAL: the Experimental build group shipped

The scope is in the private roadmap's §351: per-spec solves for the answers the build solved once and typed in, a
ladder of constraints broken from the bottom against a compromise budget, the strap derived from the case, and features
graded incubating, supported and public. This landing is the first slice the owner asked for (2026-11-20): "expose the
experimental spec parameters in the advanced appearance section", with two choices made then. A feature is offered only
where one of its builds is CLEAN, and a pick that needs other settings sets them too, after asking.

### What shipped

**A refusal is said where the viewer looks.** `SPEC` and `ROUTE_SPEC` (`layout.js`) are evaluated when the module is
imported, before `main.js` installs the boot's warning buffer, so a refusal's warning reached no instrument and no panel:
`?vph=36000` without the double barrel built the default watch, and the build's warnings read empty, exactly like the
default's. Each refusal is now also pushed to `SPEC_REFUSALS`. `main.js` shows them first in the spec panel's verdict row
("⚠ not built as asked — …") and publishes them as `__clock.specRefusals`. They are NOT build warnings, so rule 6's
silence is untouched: the watch that runs is a whole supported build, and the list is about the request.

**The group.** Appearance → Advanced → Experimental build, one dropdown per row of `src/experimental-specs.js`, each with
its tier as a badge (`data-tier`, the word only display). The value shown is read off the RESOLVED spec, so a refused
request shows as off and the verdict row says why. A pick reloads with the row's key set and its requirements applied;
when that changes a setting the viewer chose elsewhere, a confirmation names each change in the panel's own words
("Alarm: Off", "Beat rate: 36,000 A/h"). Nothing is saved in the browser: the pick travels in the link, like every spec
knob. The main beat-rate menu now shows a rate off its list (36,000) instead of a blank.

| Row | Key | Tier | Its clean build | Requirements a pick applies |
|---|---|---|---|---|
| Double barrel | `barrels=2` | incubating | `barrels=2&vph=36000&alarm=0` | the 36,000 beat, alarm off, round case, 30 h, no pulley; off also clears the beat |
| Frame on pillars | `frame=pillars` | supported | `frame=pillars` | none |
| Stop iron | `arrest=stop-iron` | supported | `arrest=stop-iron` | none |
| Sliding hands | `hands=slide` | supported | `hands=slide&case=fitted&alarm=0` | a shaped case (a round one becomes the fitted tonneau) |

**Left out, for want of a clean build**, measured on native boots: the chain pulley (`?pulley=1`, four warnings at its
best, alarm off) and the reserves the main menu does not list (12–45 h: every one warns and none re-solves its
balance). The double barrel at the default 14,400 swings the balance past the knock (three warnings), which is why its
one option builds the 36,000 watch it was solved for.

### Instruments

- `tools/probe-experimental-specs.mjs` (native, acceptance): every offered option, with its requirements applied as the
  panel applies them, refuses nothing, adds no warning to the same query without the row's key (judged by row name, the
  battery's `matchDeclaredWarns` rule; a moved row is reported: the sliding hands deepen the fitted case's own §261 row
  from 11.96 to 12.95 mm), and reads back off the resolved spec; each row's `cleanAt` boots silent. Controls:
  `?barrels=2` alone is refused and reads off, and the double barrel at the default beat warns. 18 rows.
- `tools/smoke-experimental-specs.mjs` (Chromium, acceptance): the dropdowns match the table, read off on the default,
  carry their tiers; a pick asks first and a cancel changes nothing; an accept reloads into the double barrel's build
  with the beat-rate menu showing 36,000 and no verdict; and the control, a link asking for `?barrels=2` with the alarm
  on, shows the dropdown off and the verdict naming the refusal. 16 rows.
- The usage tally (§349) records the four dropdowns' values: `barrels`, `frame`, `arrest` and `hands` joined
  `SPEC_DROPDOWNS`. `tools/probe-349-usage.mjs` passes.

### Debt and what is next

- The labels are English in every locale until a translation landing adds them (about seventeen strings across the
  locale tables); a missing entry falls back to English visibly, by i18n's contract.
- A refusal can still fall back PARTIALLY: `vph=28800&barrels=2&alarm=0` drops the rate and keeps the second barrel,
  building neither the request nor the default. It is visible now; fixing it is the roadmap's landing 0 (one spec
  schema, a refusal falling back whole).
- The rest of §351 (the schema, constraints as records, per-spec solves, the solver and its ledger, the tiers enforced
  on the main menus) is in the private roadmap.
