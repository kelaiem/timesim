## §351 — A spec solver with a constraint ladder, a compromise budget and feature maturity tiers — PARTIAL: the Experimental build group and landing 0 (one spec schema) shipped

The scope is in the private roadmap's §351: per-spec solves for the answers the build solved once and typed in, a
ladder of constraints broken from the bottom against a compromise budget, the strap derived from the case, and features
graded incubating, supported and public. This landing is the first slice the owner asked for (2026-11-20): "expose the
experimental spec parameters in the advanced appearance section", with two choices made then. A feature is offered only
where one of its builds is CLEAN, and a pick that needs other settings sets them too, after asking.

### What shipped

**A refusal is said where the viewer looks.** `SPEC` and `ROUTE_SPEC` (`layout.js`) are evaluated when the module is
imported, before `main.js` installs the boot's warning buffer, so a refusal's warning reached no instrument and no panel:
`?vph=36000` without the double barrel built the default watch, and the build's warnings read empty, exactly like the
default's. Each refusal is now also pushed to `SPEC_REFUSALS`. `main.js` shows them first in the spec panel's verdict row
("⚠ not built as asked — …") and publishes them as `__clock.specRefusals`. They are NOT build warnings, so rule 6's
silence is untouched: the watch that runs is a whole supported build, and the list is about the request.

**The group.** Appearance → Advanced → Experimental build, one dropdown per row of `src/experimental-specs.js`, each with
its tier as a badge (`data-tier`, the word only display). The value shown is read off the RESOLVED spec, so a refused
request shows as off and the verdict row says why. A pick reloads with the row's key set and its requirements applied;
when that changes a setting the viewer chose elsewhere, a confirmation names each change in the panel's own words
("Alarm: Off", "Beat rate: 36,000 A/h"). Nothing is saved in the browser: the pick travels in the link, like every spec
knob. The main beat-rate menu now shows a rate off its list (36,000) instead of a blank.

| Row | Key | Tier | Its clean build | Requirements a pick applies |
|---|---|---|---|---|
| Double barrel | `barrels=2` | incubating | `barrels=2&vph=36000&alarm=0` | the 36,000 beat, alarm off, round case, 30 h, no pulley; off also clears the beat |
| Frame on pillars | `frame=pillars` | supported | `frame=pillars` | none |
| Stop iron | `arrest=stop-iron` | supported | `arrest=stop-iron` | none |
| Sliding hands | `hands=slide` | supported | `hands=slide&case=fitted&alarm=0` | a shaped case (a round one becomes the fitted tonneau) |

**Left out, for want of a clean build**, measured on native boots: the chain pulley (`?pulley=1`, four warnings at its
best, alarm off) and the reserves the main menu does not list (12–45 h: every one warns and none re-solves its
balance). The double barrel at the default 14,400 swings the balance past the knock (three warnings), which is why its
one option builds the 36,000 watch it was solved for.

### Landing 0 — one spec schema, and nothing dropped in silence

**The table.** Every row of `src/spec-fields.js` is an object now, and its columns are the whole of what the build knows
about a key: the `field` it feeds, how its text is `parse`d, its `kind` (the rule that resolves it and decides whether the
build honoured it), where it is `offered` (`menu`, `experimental`, `url`), whether it moves arrangement metal
(`arrangement: false` for the seven keys the seat tables are keyed without), the `defaults` spellings accepted in silence,
and what it `accepts`, in plain words. Readers take it rather than restating it:
- `layout.js`' SPEC resolves every 'angle', 'step' and 'number' key through one rule per kind (`SPEC_KINDS`), the
  expressions the resolver wrote out per key before, verbatim;
- `arrangementSpec` is the one rule for the arrangement key, which `main.js` had written out four times (the arming fixed
  point, the gong-seat key, the form fit's seat lookup and the case menu's seat match);
- `usage.js`' dropdown keys are the rows not offered 'url'.

**Nothing silent.** After SPEC and ROUTE_SPEC resolve, an honoured pass walks every key the link gave and asks the table's
kind whether the build carries the value asked for (`specHonoured`). One it does not is named in `SPEC_REFUSALS` with the
value it became and what the key accepts, unless a stated refusal already named it or the value is a default spelling.
Each refusal is a `{keys, text, by}` row now: `by` is 'rule' for a resolver's stated refusal and 'unused' for the pass's.
Before this, `?vph=12345`, `?case=bogus`, `?reserveh=31`, `?barrelstep=400`, `?rsvidl=3` and 25 more each built something
other than the link said and said nothing; the spec panel's verdict row now names each.

**Not changed, on purpose.** No build moved. A refused key falls back to the spec WITHOUT that key, which is what it
always did. `vph=28800&barrels=2&alarm=0` therefore still builds the double barrel at the default 14,400, overdriven past
the knock (its three warnings); the refusal of 28,800 is named, and whether the double barrel itself should be refused
off the 36,000 it was solved for is the owner's decision, since it would remove the build the double-barrel probes measure.

**Instruments.**
- An equivalence run (a scratch script, not committed): 145 queries (the CI spec points' and a set of edge cases)
  resolved on `main` and on this tree. Every SPEC, ROUTE_SPEC, configuration key, arrangement key, drum azimuth and arrest
  choice is identical, and every refusal `main` made is still made; 30 queries gain a named refusal, none of them valid.
- `tools/probe-spec-schema.mjs` (new, pure Node, acceptance): the table's columns, the arrangement set against the seat
  tables' seven, the offerings against the Experimental group and the usage table, a refusal for every value a key does
  not take (two or three per key), none for values it does, and none from the pass on any of the 48 CI spec points. Its
  controls: a dropped field is judged not honoured for every kind, a nonsense case reaches the list, and a stated
  refusal is told apart from an unused key.
- Native boots of the default, `case=fitted`, `alarm=0&case=fitted`, `case=rect`, `case=free` and
  `arrangement=designed`, on `main` and on this tree: identical fingerprints and warnings (the arrangement key feeds the
  gong seats and the form fits, so these are the builds that would move).
