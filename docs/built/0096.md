## §96 — offline-check asserts precache coverage, not a transcribed count, and runs on every source change

Filed while landing §95 tier two, which moved the number from 23 to 27. Shipped 2026-11-02, after the number had drifted three
times in a week: #846 added `src/slide-cam.js` and nothing re-ran the check, so `main` read 115/114 until §326's `index.html` edit
triggered it on #849; #863 then read 116/115 for its own new module.

### The defect was in the instrument

`tools/offline-check.mjs` asserted "precache complete" as `counts === N`, with N transcribed by hand and bumped (with a comment)
by each landing that added a module. The number is a by-product of the stamper's walk (the seeds, every quoted `./src|vendor/` URL
in the documents, every `import` and `import()` reachable from `src/`), so it moved with any module, document, icon or vendor
file. And `offline.yml` ran on a narrow paths filter, so the change that moved it usually ran no Offline job. The failure then
landed on the next PR to touch a document, which is the misattribution §96 was filed against.

### A — the filter

`offline.yml` runs on `src/**` and `vendor/**`, which replace six narrower globs (the gong bench's, the LEGO modules', ldraw's, the
i18n tables', the glossary linker's), each added after a module slipped past the one before. Any file under either directory can be
precached, so a change there is a change to what the job measures. The job is about 2.5 minutes against the battery's 20–60, so
running it on every source change is close to free. Docs-only and roadmap-only PRs still skip it.

### B — coverage, re-derived

What "precache complete" has to mean is that **every URL the app requests is in the cache.** So the check now records every
same-origin request the offline journeys make (context-wide, so dynamic imports and workers count). After them it asserts that each
is in the cache by `sw.js`' own matching rule: an asset WITH its query, so a stale `?v=` never answers, and a document by its path
alone, so deep links load. It also asserts that none of the requests failed. `version.json` and `/__state` are excluded from the set
and still asserted NOT cached. The precache's size is printed as a report and never asserted.

Its **control** is the one §96's acceptance asked for. After the coverage check it deletes one requested module from the cache (a
primer locale table). The same predicate must then report it missing, and fetching it offline must fail. Then it puts the module
back.

Observation only sees what the journeys exercise, so the journeys are now the list that matters. A missing journey degrades
coverage rather than producing a wrong number. They were already there (index and its `?lang=de` / `?lang=zh-Hant` deep links,
explain, primer in all 23 locales, the booklet, the gong bench), plus one new one: **`technic.html` built offline.** It had been
precached since §219, but only the count stood in for its modules.

### Measured

A local run with `node tools/offline-check.mjs`: **52/52 checks pass.** The coverage row reads `112 distinct URLs requested offline,
116 cached; missing 0; failed 0`. The control row reads `/src/primer-i18n.de.js?v=…: deleted true, reported true, loaded offline
false, restored true`. Four cached entries are requested by no journey, which coverage permits (requested must be cached, not the
reverse).

Adding a module under `src/` now changes no expectation anywhere: either a journey requests it and it is covered, or none does and
it is reported in the size and nowhere else. `CLAUDE.md`'s description of the job is updated to say this.
