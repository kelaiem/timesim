## §303 — LEGO role colours re-picked so BrickLink lists every line

Owner: "Repick colors." §301 put BrickLink behind the parts list and found 19 of
143 lines across the eight 2026 builds (15 distinct (part, colour) pairs) in a
colour BrickLink lists no element for, and left the role colours alone because
re-picking them was the owner's call. This landing re-picks them. Display only:
no placement, matrix or geometry moved; the only change to a `.ldr` is the
colour column, and the page's own role palette is untouched.

**The constraint (rule 1), written once.** A line is a (part, colour); BrickLink
sells it only if its Codes download lists an element for that pair. So every
(role, part) the builds place must take a colour with `listed(part, colour)`. The
unit is the (role, part) pair, not the role: a role can place several parts and
BrickLink lists some of them in ONE colour (7785 White, 7861 Light Bluish Gray,
69778 Blue, 18946 Red), so no single colour exists for `spur` or `detent`. The
role's row in `LDRAW_COLOUR` stays its default; a `role/part` row is an
EXCEPTION for a part the default is not listed for (five of them).
`repickColours` (`src/technic-colour.js`, pure) solves it, with its preferences
written in its header, in order: the fewest exceptions, the base palette before
any extension, the role's current colour, the fewest NEW same-part merges, the
fewest roles in the same build already wearing the colour, the colour most other
roles give that part, the lower code. `LDRAW_COLOUR` is no longer typed: the probe
re-runs the solver from the §300 table (`COLOUR_BASELINE_300`, kept for that) and
fails if the shipped table differs, or if re-picking from the shipped table moves
a row.

**The palette is extended by one colour, and why.** BrickLink lists the 20-tooth
gear 69779 in Dark Azure and nowhere else, so none of the ten colours works for
it. LDraw code 321 (Dark Azure, `#469BC3`, typed from LDraw.org's published
definition into `COLOUR_INFO`, a display value like the others) joins, and
`LDRAW_NAME` in `tools/bricklink-subset.mjs` names it for BrickLink (matched by
name against Colors.txt). Nothing else needs it: the probe fails an extension
colour used where any base colour is listed. `src/technic-bricklink.js` was
regenerated (11 colours); `--check` re-derives it from the downloads.

**The unofficial gears.** 7785 (the detent wheel) is now White, the only colour
BrickLink lists it in (element 6569662), and 7861 stays Light Bluish Gray (element
6576953). Both print listed and flagged unofficial, as before.

**Merges (roles that shared a build and had different colours, now one).**
`tools/technic-colour-repick.mjs` prints them all (25 pairs). By new colour: White,
joiner with crown, hook, knob and tile and the detent wheel with them; Black, the
rotor with the axles and the stub; Yellow, the barrel with the great wheel and the
axle 60485 with the lever; Dark Bluish Gray, the rack with the driving ring and the
Technic brick; Blue, the pins with the wheel; Red, the 16T clutch gear 18946 with
the catch and the follower; Green, the alarm's beam with the baseplate (different
builds' parts, one build in common); Orange, the arm with the ratchet. **No two
roles that place the SAME part in one build were merged** (the probe holds new
same-part merges as the fourth preference, and the report marks them with `*`:
none), so no BOM line folded: the lines per build are unchanged.

The probe's gate covers more than the lists: every (role, part) unit over both
generations, every keyless mode and every alarm state (74 units), and every
placement's `.ldr` colour. Controls: 7785 forced to Orange is flagged "lists
White" by the unchanged flag path and fails the unit, derivation and table gates
(eight rows red when the table is edited that way); 69779 moved back to Light
Bluish Gray fails the unit gate; the solver THROWS when no palette colour lists a
part (7785 removed) and when the extension is withheld; the §300 table has
unlisted lines the gate would count. The flag code path and the CSV's
`bricklink_listed` column stay, and the page's colour sentence now says the
colours were re-picked to be listed ("would say" if one were not).

**Decisions to flip.** The re-pick trades the §300 reading (a role's colour tells
its job) where BrickLink forces it: the pins and the alarm's wheel are both blue,
the detent wheel is white, three parts of `spur` wear three other colours. The
alternatives are to buy in the listed colour and keep the picture (the §301
option), or to extend the palette further for a part with a grey BrickLink
lists that the ten do not (22253 is listed in Dark Gray and Light Gray, 3482's
old greys). Neither is taken.

**Instruments.** `node tools/probe-technic-bom.mjs` — `PASS — 2167 checks, 35
controls, 0 failed`; `node tools/technic-colour-repick.mjs` (report; exits 1 if the
table differs from the derivation); the other technic probes unchanged. The
battery cannot see any of this (`src/technic-*.js`, `technic.html`, `tools/**`).
