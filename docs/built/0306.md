## §306 — BrickLink wanted-list XML export per LEGO build

Owner: yes to a BrickLink wanted list per build, "so a builder can upload one file and
buy a whole build". Display only, beside §300's CSV: no placement, matrix, colour or
`.ldr` line moved.

**The format, and where it is from.** BrickLink's wanted-list upload (Wanted > Upload >
BrickLink XML): an `<INVENTORY>` root, one `<ITEM>` per lot carrying `ITEMTYPE` (P),
`ITEMID`, `COLOR`, `MINQTY`, `CONDITION` (N, U or X), `REMARKS` and `NOTIFY` (N), in that
order and nothing else. It is written down from BrickLink's published upload format as
known to the author: bricklink.com answered the sandbox with a bot check, so the
element set was NOT re-read on the day, and it is kept to the minimum that format
documents. No `<?xml?>` declaration, no comment and no wanted-list name tag (the list
is named on BrickLink's own form; a tag the format does not have would be a guess).
The module header (`src/technic-bom.js`, `wantedListXml`) carries the same statement.

**Rule 1 here is "never typed".** `ITEMID` is `line.bricklink.item` and `COLOR` is
`line.bricklink.colourId`, both from §301's generated subset; the LDraw id appears only
in `REMARKS`. Seven placed ids are bought under a different number and the export
carries BrickLink's: 22253 → 6595, 75924 → x127c20pb01 (the string), 3023b → 3023,
3070b → 3070, 32123a → 4265c, 4032a → 4032, 4185a → 4185. The
string's lot says the model's stud count (21) in `REMARKS`, because BrickLink sells
the 20L and 21L under one item (§301's open decision, still the owner's to confirm).

**Lots, not lines.** A BOM line is an (LDraw id, colour); a BrickLink lot is an (item,
colour). Lines that map to one lot are merged with their quantities summed and the
merge is reported (`wantedListOf().merges`, shown under the link). **Measured: no
build merges anything today** — every build's lots equal its lines:

| build | technic_2026 lots / parts | technic_classic lots / parts |
|---|---|---|
| row 1 | 11 / 59 | 11 / 64 |
| row 2 | 11 / 38 | 11 / 38 |
| row 3 | 10 / 44 | 9 / 43 |
| row 4 | 11 / 26 | 11 / 26 |
| keyless | 28 / 189 | 26 / 187 |
| fusee | 24 / 73 | 24 / 73 |
| alarm | 27 / 214 | 27 / 214 |
| escapement | 20 / 46 | 20 / 46 |

**It refuses rather than guesses.** A line with no BrickLink item, no BrickLink colour
id, a quantity that is not a positive integer, or no element BrickLink lists in its
colour throws, naming the line, and the page shows "no BrickLink wanted list: …"
instead of a link. Since §303 no line does.

**The page.** technic.html's parts list offers "BrickLink wanted list (.xml)" beside
the CSV with a condition picker (any X, new N, used U), the lot count, and the note
(`WANTED_NOTE`): generated from the model and BrickLink's catalogue download of
2026-10-20 (read from the subset's own date), not checked against stock or prices;
modelled, not built. booklet.html's header offers the same file (condition any).

**Instruments.** `node tools/probe-technic-bom.mjs` — `PASS — 2322 checks, 47
controls, 0 failed` (a WANTED section: 16 lists × 3 conditions parse back through the
module's strict parser and an independent regex read; the lots equal the BOM's (item,
colour) multiset re-read through the subset, quantities summing to each BOM's total,
every ITEMID and COLOR in the subset, the tags exactly the format's, escaping of
`& < > " '` round-trips. Controls seen to fail: 22253 written for 6595, a MINQTY
changed, an ITEM dropped, a COLOR changed, an invented tag, a lot written twice; an
unlisted line, a line with no item and one with no colour id refusing to export; a
bad condition refused; a synthetic mould-variant line merged, summed and reported).
`node tools/smoke-technic-bom.mjs` (Chromium, 1280 and 390 wide): the row 2 and fusee
downloads are byte for byte `wantedListXml` at condition any and after choosing new.

**Not done.** The upload itself was not tried (no BrickLink account or network from
here); the first owner upload is the format's real test, and a tag BrickLink rejects
is a one-line change in `wantedListXml`.

**Follow-up: a copy button.** The owner's first try found BrickLink's Wanted > Upload page does not accept the
downloaded file; it takes the XML pasted into its box. So beside each download (`technic.html`'s parts list and
the booklet's header) a "copy for BrickLink" button puts the same `wantedListXml` text, at the condition chosen,
on the clipboard (`src/technic-clipboard.js`: the Clipboard API, then a selected textarea where the page is not
allowed it), and says where to paste it. `smoke-technic-bom.mjs` reads the clipboard back and holds it to
`wantedListXml` at the picked condition, with the condition as its control. `offline-check.mjs`'s precache count
is 98 (the one new module). The pasted upload itself is still unchecked from here.
