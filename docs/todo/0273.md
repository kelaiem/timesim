## 273. Outlines wrote seam points twice: 60 shapes from five builders — DONE

TODO 265's residue. The alarm cam's step was a SEAM WRITTEN TWICE: two pieces
of one outline each emitted the point they share, equal in algebra and
computed two ways. three.js `Shape.getPoints()` drops a repeated point only
when it is EXACTLY equal to the one before, so the JS engine's last ULP decides
whether the copy survives as a sliver edge. A bevel offsets each contour point
along its edges' bisector, and a sliver has no direction to read. TODO 265
fixed the cam, because a vertex mean read as an axis turned its slivers into a
3e-3 `lineSpec` failure on Chromium 156. Its survey found 60 more extruded
shapes carrying the same class. TODO 265 recorded that they moved no verdict,
only the fingerprint and seven §152 digests between browsers. That was true of
the difference BETWEEN browsers; on either browser the slivers were cutting
metal (below).

**What the survey measured.** It walked every extruded shape's AUTHORED curves,
outline and holes, for consecutive points under 1e-9 apart.
- The 60 shapes' doubled seams were exact copies or slivers, the largest
  3.97e-15. TODO 265's record had called the cam's survivors 1e-10 slivers; the
  measured size is ~1e-15, and that line and the `ci-env-upgrade` skill are
  corrected.
- The finest step any outline means to take is 1.087e-5 (the alarm arrest
  cross's), then 2.125e-4.

The 60 came from five builders, and each now writes the seam once, from the
piece that owns it:

| Builder | Shapes | The seam, and who owns it now |
|---|---|---|
| `cycloidalToothPath` (`geometry.js`) | 40 | The addendum face's last sample is the tip land's corner (`tipR = Rp + h` exactly). The face loops stop one short, and the tip land writes the corner. A boot warning fires if the face's top ever stands farther than the profile's chord tolerance from that corner, because then dropping it would cut a real step. |
| `crescentLand` (`main.js`) | 16 | The collar's two ends are the seat rim's ends, where the circles cross, already written by the rim loop and reached again through `acos`. The collar now writes only its interior samples. |
| `makeHeartCam` (`geometry.js`) | 2 | `i = N` is `i = 0` again; the loop runs `i < N`. |
| `makeEscapeWheel` (`geometry.js`) | 1 | Each tooth ended on the next tooth's valley point, which the next tooth wrote again. The valley is now written once: the first tooth's `moveTo`, and the last tooth's curve ends on it. |
| `makeCock` (`geometry.js`) | 1 | The outline opened on a point the arc then re-derived. It now opens on the arc's OWN first point (TODO 196's rule for the plate rim). |

**The slivers were cutting metal, and the layout read it.** All 40 gears are
bevelled. Each surviving sliver gave the bevel a garbage bisector at a tooth's
tip corner, so the corner was thrown outward past the tip.
- Measured on `main`: 22 bevelled gear meshes stood proud of their own tips.
  The fix lowers each outer radius by 0.012 to 0.027 (the great wheel
  15.654 → 15.643, the alarm detector wheel 5.218 → 5.192) and drops about 10%
  of their vertices.
- The build's clearance searches read obstacle metal off these meshes, so
  with the spikes gone they land on different candidates. Three searches
  re-solve, each read off its seam's visit count:
  - the power reserve's swing (`solveReserveSwing`, seams 58–60), which moves
    the differential, the geneva finger and the sub-idler;
  - the alarm winding idlers (seam 248);
  - the stations searched at seam 337.

  The escape-wheel fix moves nothing alone, but together with the gears it
  also re-places the keyless stem's train, by up to 1.6 along the stem.
- Each placement is deterministic per tree: a re-boot of either tree moves
  nothing. It was measured with the live loop held and the inputs reset, as
  the battery runs. Without that hold the comparison is noise; the first
  capture here was.
- Because the searches iterate differently, §267's boot-bar table no longer
  described the build: `boot-yield` read the bar 18.1 points off the clock
  against its 17.5 backstop. `tools/boot-progress.mjs --write` re-measured it,
  and the probe reads 6.9 points worst and 1.0 on average.

These moves are the layout answering truer metal. Whether the new layout is
clean is the battery's to say, run whole on this change.

**The gate.** `outlines` gains a fourth tier: any authored curve shorter than
`SEAM_GAP_MAX` fails. It reads the curve's own `getLength()`, not its chord,
because a full-circle arc starts where it ends. It reads the authored curves,
not the sampled ring, because `getPoints` has already hidden the exact copies.
`SEAM_GAP_MAX = 2e-10` classifies two measured populations, as
`DECLARED_CONTACT_REACH` does:
- doubled seams measured at most 3.97e-15;
- intended steps measured at least 1.087e-5.

That is ten orders of magnitude apart. The threshold is their geometric middle,
rounded, so either side can move five orders before it misclassifies.

**Controls.**

  requires none from the clean square, the holed square and the two
  full-circle bore shapes.
- Run against `main`'s geometry, the tier reads exactly the survey's 60 shapes.
- On the fixed tree it reads 0, and boot is silent.
