## 265. Chromium 156 builds different alarm-strike metal from the same source: an ill-conditioned build step — DONE

Found bumping Playwright 1.56.1 → 1.64.1 (#762), which GitHub's move of
`ubuntu-latest` to Ubuntu 26.04 forced: 1.56.1 cannot install Chromium there.
On the self-hosted Linux/ARM64 host, the same source (`main` at `abcceb8`; the
PR touched only `tools/`) built under Chromium 141 (the 08:08 UTC nightly,
2026-10-22) and under Chromium 156 (#762's battery) gives two movements:

| | Chromium 141 | Chromium 156 |
|---|---|---|
| fingerprint (both virgin boots agree) | `955951544` | `4180065205` |
| meshIntegrity tris / zeroArea | 491,235 / 21,449 | 491,223 / 21,441 |
| `lineSpec` | PASS | FAIL |

The failing rows are all in the `alarm strike` reference (tol 1e-6):

| key | spec | measured (156) | Δ |
|---|---|---|---|
| `pivSwD` | 9.813240 | 9.816065 | +0.00283 u |
| `restGamma` | 0.2094395 rad | 0.2093110 | −0.000129 rad |
| `camPickupR` | 3.710164 | 3.712336 | +0.00217 u |
| `lift` | 1.439941 | 1.440849 | +0.00091 u |

Every other gate passed under 156, `strikeHandoff` included, and so did the
determinism gates (each browser agrees with itself across virgin boots). A new
JS engine changes `Math.*` results by ULPs, about 1e-16. The build moved by
about 1e-3 and lost 12 triangles. So some step amplifies float noise by about
10¹³, which makes it discontinuous or ill-conditioned: a solve that picks a
branch, a bisection whose stopping test lands on a different step, or a
tessellation or earcut decision fed by a coordinate sitting on a threshold.
That is a defect of the build, not of the browser. Rule 1 says a constant is
derived from its constraint, and a derivation that moves 1e-3 under a ULP has
not pinned the constant to the constraint. §261's link seat solve was already
found discontinuous at the nose's own station, so that neighbourhood is the
first place to look.

The run's §152 incremental path also did step 1 below for free: against

Several of them are fixtures or wheels a layout solve places, so a shared

**Fix path.**
1. Localise: boot both browsers on one host and diff `unitDigests()` (§152)
   at the build pose. The first unit whose SHAPE digest differs names the
   step (a PLACE-only difference points at a pose law, not a cut). Two
   Playwright installs (1.56.1 and ≥ 1.61) in separate directories give the
   two browsers on one host.
2. Re-condition that step so a perturbation of its inputs at the ULP scale
   moves its output at the ULP scale: take the branch from the constraint
   rather than from a float comparison, close the bisection on the residual
   rather than an iteration count, or snap the coordinate a tessellation
   decision reads. Add a probe that perturbs the step's inputs by a few ULPs
   and holds the output to float noise, with a control that restores the
   current code and fails.
3. Confirm `lineSpec`'s four rows land on their spec under BOTH browsers, then
   land the Playwright bump and return the five jobs to `ubuntu-latest`
   (#762's other two CI fixes, the dpkg lock wait and offline-check's
   per-boot watchdog marks, are already on `main`). On 26.04 `install-deps` needs ~25 MB of
   fonts; #766's apt cache covers that.

**Localised and fixed on 2026-10-23: a seam written twice in the alarm cam.**
Step 1 was done without Chromium 156, which this container cannot download.
An engine change moves a transcendental result by an ULP per input, so 141
was booted with `Math.*` nudged by ±1 ULP, keyed on a hash of the arguments
and a seed. A uniform scale reproduced nothing, because it keeps every
comparison's order. Seed 2 failed exactly 156's four rows (pivSwD +2.83e-3,
the same figure), and bisection by function left `Math.atan2` alone. The cam's
outline wrote two points per lobe twice. The dwell began at the previous
drop's last point (`tip − pitch + dropSpan`), and the approach ended at the
rise's first (`lobe + rise[0].psi`, at `ALARM_CAM_PICKUP_R`, which is
`rise[0].r`). Each pair is equal in algebra but computed two ways, the rise
through `atan2`. three.js drops a repeated point only when it is EXACTLY
equal, so the engine's last ULP decided which copies survived as 1e-10
slivers: degenerate triangles (the `zeroArea` count), and an uneven point
count per lobe. `lineSpec` reads the wheel's axis as the outline's vertex
MEAN ("four identical lobes"), so each survivor pulled it by about 3e-3.
Chromium 141 passed by symmetry, not by construction: its two survivors
started lobes 0 and 2, 180° apart, and cancelled. The fix writes each seam
once, from the piece that owns it, and a boot guard warns when two
neighbours sit closer than half the flank's finest step.
`tools/probe-265-ulp.mjs` holds it. The shipped tree, unperturbed and under
seeds 2, 5 and 7, has 0 `lineSpec` failures and a silent guard. The CONTROL
restores the doubled seams under seed 2 and fails the four strike rows
(pivSwD +1.97e-3) with the guard warning.

**Residue, measured and not fixed here.** A survey of every extruded shape's
raw outline found 60 with consecutive points under 1e-9 apart, mostly gear
tooth outlines: exact copies three.js drops, or 1e-16 slivers it keeps. That is
the same class, and very likely why seven units' §152 digests differ between
the two browsers when only the cam fails a gate. Nothing else reads a vertex
mean as an axis, so those shapes change the fingerprint, not a verdict.
Nudging every transcendental function at once (seeds 2 and 11) also tripped
three boot asserts that sit on a threshold, none of them in the cam: TODO 221's
beak relief bracket, §173's "backward flank 0.0000° off radial" (an exact-zero
test) and TODO 15's centre-pinion gauge (8 gaps for 7 teeth). `lineSpec` held
in both runs. Step 3 still owes Chromium 156 itself, which only CI can run.

**Step 3: Chromium 156 measured green with the fix, and the bump lands.**

the doubled seams in the 60 other shapes, which move no verdict. The bump to
1.64.1 and the return of the six browser jobs to `ubuntu-latest` follow in one
PR. The item closes when that PR's battery is green on 26.04.
