## 313. The alarm-free build publishes no energy record, so the equalisation gate passes it without measuring

Filed 2026-11-15, from TODO 292's start measurement on `alarm=0` (`tools/probe-292-fast-start.mjs`), which found
`__clock.equalisation` undefined on every alarm-free build.

**What is wrong.**
- **The going train's whole TODO 32 record is computed inside the alarm module.** `const EQUALISATION = (() => { … })()`
  sits inside `async function buildAlarm()` (main.js, from line 25680). Its names leave through that function's return
  (`… ARREST_Z, EQUALISATION, GONG_A1 …`), and are destructured at `} = ALARM_BUILT ? await buildAlarm() : {};`. With
  `?alarm=0` that is `{}`, so `EQUALISATION` is `undefined` and `get equalisation()` returns it.
- **The record carries far more than the alarm's half.** It holds:
  - the going spring's law (`going.k_Nm_per_rad`, its section, packing and stress);
  - the set-up's quantisation and the level product;
  - the whole ENERGY COLUMN (`going.energy`: released energy, escape torque, the friction corners, every pivot's stress,
    the maintaining hold, the amplitude claim, peak, target and start, the reset coupling, the oil ageing).
  
  None of those is the alarm's. An alarm-free build cuts the same going train and publishes none of it.
- **The gate passes it, silently.** `checkEqualisation` (inspect.js) opens with
  `if (!E) return { ok: true, error: 'no equalisation payload on __clock (main.js TODO 32 block missing)' };`. So on every
  alarm-free build, `equalisation` reads PASS having held nothing: no level product, no ribbon stress, no amplitude.
  That includes the validated `alarm-free-fitted` and `stopwork-140` points, and TODO 298's 36/36 on
  `alarm=0&case=fitted`.
- **The rest of the going-side publication is outside the alarm block.** `GOING_POWER`, `BALANCE_DRIVE`
  (`balanceDriveModel`) and the oscillator are all published there. So the build CAN state the going half without the
  alarm; it simply computes it in the wrong scope.

**Why it matters now.** A balance or spring change on an alarm-free build is not judged by rows 13–18 at all. TODO 292
had to measure the 36,000 row's start off `balanceDriveModel` instead of `amplitude.target`, because the target's step
test lives in the record.

**Fix path.**
1. **Split the record by module.** The going half (`going`, including `energy`) moves out of `buildAlarm` to the module
   scope. It stands after the going train's metal and `GOING_POWER`, which it reads. The alarm half (`alarm`) stays
   behind `ALARM_BUILT`.
   - `EQUALISATION` becomes `{ going, alarm }` with `alarm: null` when the module is not built.
   - Its other consumers inside the alarm block (`ARREST_STALL_NMM`, the alarm idler's transfer row) keep reading
     `EQUALISATION.alarm`.
2. **Make the gate refuse an absent record.** `checkEqualisation` FAILS when `going` is missing. It stands the alarm rows
   down only on the build's own word (TODO 298's `clock.modules`, the `modules` gate's rule), counting them in
   `standDown` like every other table.
3. **A control.** Boot `alarm=0` with the going half deleted, and require the gate to fail.

**Acceptance.**
- `__clock.equalisation.going.energy` is published on every alarm-free build.
- `equalisation` holds its going rows there (the battery at `alarm=0&case=fitted` reads them, not the empty-payload
  pass).
- The alarm rows stand down by the module word.
- An absent going record fails.
