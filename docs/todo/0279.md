## 279. Generated gong files are not gated: gong-bench-data went stale on main unseen, and gong-seats --check is unrun

Filed 2026-11-01. Found closing #851 (the form rectangle's reach to the drum), whose PR body had to say "I expect
`src/gong-seats.js` and `src/gong-bench-data.json` unmoved, but that is unproven here" because nothing proves it.

**What is wrong.** Two committed files are GENERATED from booted builds and never edited by hand:

- `src/gong-seats.js` by `tools/gong-seats.mjs` — where the alarm gong stands in each fitted form case and what it rings;
- `src/gong-bench-data.json` by `tools/gong-bench-data.mjs` — the measured free space `gong-bench.html` lays a wire into.

Each tool has a `--check` that re-derives the file and compares it with the committed one. **Neither check runs in any
workflow or in `tools/ci-battery.mjs`** (`git grep` for either tool name under `.github/` and `tools/ci-battery.mjs`
returns nothing; the only mentions are the tools themselves and `docs/built/0310.md`). So the files are held to their
builds only by someone remembering. They were not: on 2026-11-01 `gong-bench-data.mjs --check` FAILED on `main`, and
failed identically on `0869dc01`, the commit before #851, so it was already stale before that landing. All four cases
(rect, cushion, tonneau spiral; fitted bar) differed in `pillars`, the free-cell map and the cell counts — the pillars
had moved since it was generated. It was regenerated by #852 (`--write`; `--check` and `tools/smoke-gong-bench.mjs`
pass). What last moved the pillars was not isolated (no bisect).

**What is not known.** `tools/gong-seats.mjs --check` was started on the merged tree (`b74cc0eb`) and never finished: it
iterates each case through up to five fixed-point rounds and its log stopped partway through the bar seats on the
cushion/tonneau, with no verdict and no exit line (the background shell was lost). So whether `src/gong-seats.js` is
stale too is UNKNOWN, not clean. Its first rounds did print refusals (a seated build adding a warning the first fit
lacks; `CASE_WIDTH_MAX` exceeded) that are the generator's ordinary candidate rejections, not a verdict.

**Why it matters.** The seats are solved against the pillars (TODO 272: the gong chooses first, the pillars yield to
its footprint), and the bench draws the same band map; a stale seat table means the build "re-measures the band… and
warns if the seat no longer holds" (`docs/built/0310.md`) at boot on form builds, and a stale bench map shows free space
the built metal has taken. The class is the one standing rule 7 names for digests: a claim about the metal that nothing
re-derives is not anchored.

**Fix path.**
1. **Run `node tools/gong-seats.mjs --check` to a verdict**, detached from the session (it takes far longer than a
   foreground tool allows; the earlier attempt ran ~30 min without finishing), with Playwright's Chromium. If it fails,
   regenerate with `--write` (one kind: `--write rect`) in its own PR and say what moved.
2. **Gate both.** Decide where the check lives and put it there: a workflow (path-filtered to the files that move the
   metal they read — `src/main.js`, `src/layout.js`, `src/gong-*.js`, `tools/gong-*.mjs`), like `offline.yml` and the
   Explainer workflow, not the battery. Price it first: `--check` costs the same as `--write` ("a few minutes" per
   `gong-bench-data`, much more for `gong-seats`), so measure both on the CI host before choosing between every PR
   and a nightly. Never re-derive a job cap from one local run (`battery.yml`'s 1.66x same-tree spread).
3. **Say it in the PR template or CLAUDE.md** if it stays manual: the "Instruments" section should name these two
   commands for any change to the form rectangle, the pillars or the gong seats.

**Done when.** `gong-seats --check` has a recorded verdict on `main`; both checks run somewhere a stale file cannot
merge unseen (or the decision to leave them manual is written in CLAUDE.md with its reason); and this item cites the PR
that did it.
