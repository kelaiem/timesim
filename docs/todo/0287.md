## 287. The gong seats table has drifted from what tools/gong-seats.mjs derives, and the tool cannot always finish

Filed 2026-11-05, found while landing §329's flip (PR #892).

**What is wrong.** `src/gong-seats.js` is GENERATED (§310 landing 2): each fitted form case's gong seat, solved by
`tools/gong-seats.mjs` from booted builds, never typed. `--check` re-derives it and compares. On 2026-11-05 two complete
`--check` runs failed, one on clean `main` and one on the flip's branch:

    spiral: no seat the lever reaches
    fitted spiral: the fit and the seat did not close
    fitted: no spiral seat closes — its default is the bar
    FAIL: src/gong-seats.js is not what the tool derives — run `node tools/gong-seats.mjs --write`

The check does not say which row or field differs, so the size of the drift is unknown. The committed rows are the rect,
cushion and tonneau spirals and the fitted case's bar, each with the fit it was solved at.

**And the tool cannot always finish.** Two later runs (`--write`, then `--check`, both on `main`) died on a boot that never
produced a page: `page.waitForFunction: Timeout 600000ms exceeded` (`tools/gong-seats.mjs:105`). The first died among the
cushion's bar candidates, the second among the rect's. Before the cushion run died it also recorded why its bar candidates
were refused: their seated builds break the 40 mm owner cap (the form case 40.75 and 40.58 mm across its short side), or
let the alarm hammer govern the caseback skirt's floor (§198). So a candidate's seated build can wedge or run past ten
minutes, and which candidate does is not fixed.

**Why nobody saw it.** No workflow runs `tools/gong-seats.mjs`, `--check` or otherwise. The build re-measures the band at
boot and warns if a seat no longer holds, and no swept point warns, so the seats still hold on the builds the battery
boots. The table is stale against its own generator, not broken in the metal.

**Fix path.**
1. Make `--check` say what moved: per kind and seat, the committed and derived fit, length, fundamental and wire path, so a
   drift can be read before it is rewritten.
2. Find the wedge: give each candidate boot the spec-tier treatment (`tools/ci-battery.mjs`' `SPEC_BOOT_RATIO`), a timeout
   scaled from that boot's measured cost and a dead or wedged verdict instead of an uncaught throw, and log the candidate's
   query, so the hanging seat can be booted alone.
3. Re-derive with `--write`, read the diff against the committed table, and land it with the reason each seat moved.
4. Run `--check` somewhere: on the explainer-speed workflow it is too slow (minutes per kind), but a weekly or on-demand
   job, or a battery probe on the PRs that touch the alarm module or the form cases, would stop the next drift going unseen.

**Acceptance.** `node tools/gong-seats.mjs --check` completes and passes on `main`, and some workflow runs it.
