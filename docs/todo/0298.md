## 298. The battery cannot judge a build without the alarm: its tables name the alarm's units, and the alarm-free build has never been swept

Filed 2026-11-09, out of BACKLOG §339 2b′. The owner's question there was whether a different going-train
arrangement could shrink the alarm-free fitted case (`?alarm=0&case=fitted`). That needs the battery's verdict on an
alarm-free build, and it was the first time anyone asked for one.

**What is wrong.** §325 landing 3 made the alarm a MODULE: `?alarm=0` builds the movement without it, and `main.js`
branches on `ALARM_BUILT` at 103 sites to leave the module's metal uncut. `src/inspect.js` has no notion of that at all.
Its tables (`MECH_GRAPH`, the hand-off rows, `PLATE_SEATS`, `INTRA_UNIT_CONTACTS` and its floors, `LUBRICATION`, the
penetration budgets, the clearance tables, the expected-contact floors, the line specs) are written for the build WITH
the alarm. Run against an alarm-free build, they fail on every row that names an alarm unit, and three checks throw.

Measured with the native battery (`node --import ./tools/native/loader.mjs tools/battery-native.mjs --query
'alarm=0&case=fitted&barrelstep=-20&rsvaz=0&alarmmod=50&rsvidl=2' --shards 4`, the alarm-free fitted case at the
default arrangement, on c19459f8, this branch: main at 14a1f8c1 plus §339's report probes), 13 gates fail and 3 throw.

**Rows that name a unit the module did not build** (the bulk; a module-aware battery stands them down):

| check | rows | how it fails |
|---|---|---|
| `support` | 36 | `unresolved: Alarm …` |
| `graph` | 28 | `missingFromScene`, every alarm unit |
| `alarmHandoffs` | 32 | `ERROR`, mesh missing |
| `strikeHandoff` | 4 | `ERROR`, mesh missing |
| `penetration` | 11 | `ERROR: unit missing` |
| `plateSeats` | 36 | `malformed: names no mesh` |
| `intraUnit` | 139 + 3 | unmatched selectors; floors on `no such unit` |
| `lubrication` | 15 | `stale: unit label(s) … not registered in the scene` |
| `clearances` | throws | `no unit labelled "Alarm lock"` |
| `expectedContacts` | throws | `no unit labelled "Alarm link"` |
| `lineSpec` | throws | `clock.lineLaws`' getter builds on an alarm object that does not exist |

**Real findings on the alarm-free metal** (what a module-aware battery must leave standing):

- **The setting lever stands in the case middle**: `inspection` FORBIDDEN `Case ⇄ Setting lever`, `undeclaredClearance`
  0 at `beat f=0`, `sweptOverlap` CONFIRMED (0.793 overlap), and two `plateSeats` rows (`hackRodPin` and a cylinder of
  the setting lever, contact). One defect seen by four checks.
- `plateSeats`' `Case / caseMiddle` seat is STALE on this build (never within the margin of the plate).
- `outlines`: the three-quarter plate's outline crosses itself once (rings 144/146 at (7.81, −35.48)).
- `restoring`: the maintaining detent and the minute jumper read restored by nothing (`fanout 0`). Whether that is the
  metal or an alarm-named declaration is not yet read.

**Why it matters.** Every alarm-free build (round, the four form kinds, `case=free`) is unvalidated: none is in
`src/validated-configs.js`, and the one alarm-free spec point (`stopwork-140`, `case=free` at its own arrangement) is
swept by the point tier's three sweeps only. So a part through another part on an alarm-free build ships under a green
board, and the setting lever above is one. It also means no arrangement can be adopted for the alarm-free builds:
§339 2b′ measured escape −30° / balance 40° at 902.7 mm² against today's 944.5, with no finding beyond the
reference's, and could not land it, because "no finding beyond the reference's" is not a verdict CI can give.

**Fix path.**
1. **Module awareness.** One declaration of which `MECH_GRAPH` units the alarm module owns, and the build publishing
   which modules it built. Every table row naming an absent module's unit then stands down, is counted, and is
   reported by name. Three controls:
   - On the default build nothing stands down.
   - On an alarm-free build every declared module unit is absent from the scene. A declared unit present while its
     module is absent fails, and so does an absent unit that is not declared.
   - A row standing down names only absent units of absent modules. A row naming a missing unit of a BUILT module
     still fails exactly as now.
2. **The real findings**: the setting lever out of the case middle, the plate outline's crossing, the two `restoring`
   rows read and fixed or waived against this item.
3. **An alarm-free spec point** in `tools/ci-battery.mjs`' `SPEC_POINTS`, swept, so CI judges the alarm-free metal on
   every PR. That point is where an alarm-free arrangement (§339 2b′'s escape −30° / balance 40°) can then be judged.

**Acceptance.** `battery-native.mjs --query` on the alarm-free fitted case runs every check with none throwing, every
failing row is a real finding (not an absent unit), the three controls above hold, and an alarm-free point sweeps in CI.
