## 315. probe-204-rates still expects an undriven rate to fall back to the 18,000 watch, which section 343 retired

Filed 2026-11-15, found while landing §339 3d (the 36,000 A/h row's balance at `?barrels=3`).

**What is wrong.** `tools/probe-204-rates.mjs` holds the TODO 292 refusal: a `?vph=` whose `RATE_TABLE` row is
`undriven` must build the shipped watch, not a stale balance.
- It writes the shipped watch as a LITERAL: `r.vph !== 18000 || r.row !== rows[18000].row` (line 89), with the same
  figure in its header (line 12) and its OK line (line 91).
- §343 landing 3 made 14,400 A/h the shipped watch (`DEFAULT_VPH`). The refusal now builds the 14,400 watch, as
  `layout.js` intends, and its warning says so.
- So the probe FAILS on `main`, for both undriven rates:
  - `?vph=28800 built SPEC.vph 14400, fourth row 8/64 @ 0.2625 — not refused to the 18,000 watch (8/80 @ 0.21)`;
  - `?vph=36000`, the same line.
  
  Measured on `main` at 1f68bf9d, and identically with §339 landing 3d applied.
- **The refusal is right and the probe is wrong**, so a reader trusting the probe is told the build regressed when it
  has not. The probe runs in no workflow, which is how the stale literal went unnoticed.

**Fix path.**
1. Read the shipped rate from `layout.js` (`DEFAULT_VPH`, and its row from `RATE_TABLE`), never a typed figure.
2. Hold the refusal against that, and say so in the header and the OK line.
3. A control: patch `DEFAULT_VPH` in a child boot (`tools/native/source-patch.mjs`) and require the probe to follow
   it. A probe that typed the default would fail the control.
4. Since §339 landing 3d a row may carry a `parallel` balance that `?barrels=3` drives. The probe should also hold that
   the 36,000 row is refused on the one drum and built at `alarm=0&barrels=3` (today
   `tools/probe-339-barrel-b.mjs` row 6 holds the second half).

**Acceptance.** `node tools/probe-204-rates.mjs` passes on `main`, reads the shipped rate from `layout.js`, and its
control fails when the default is patched and the probe is not.
